# AI Document Q&A

Upload your documents and ask questions about them. Answers are **grounded only
in your files** and come with **cited sources** — a complete, local-first
Retrieval-Augmented Generation (RAG) application.

Built with **FastAPI**, **FAISS**, and a **Streamlit** chat UI. It runs fully on
your machine using **Ollama** (no API keys, no cloud, no cost) and can switch to
OpenAI or `sentence-transformers` with one setting.

---

## Why it's useful

Large language models often "hallucinate" answers. This app answers **only from
the documents you upload**, shows exactly **which chunk each answer came from**,
and clearly says *"I could not find the answer in the provided documents"* when
the files don't cover the question — so you can trust the output.

## Features

- 📥 **Upload PDF, TXT, or Markdown** (multiple files at once).
- ✂️ **Smart chunking** with overlap and sentence-aware boundaries.
- 🔎 **Semantic search** over a persistent **FAISS** vector index (survives restarts).
- 🧠 **Grounded answers** generated by an LLM using only retrieved context.
- 📌 **Source citations** — every answer lists the file, page, and relevance score.
- 🚫 **Honest "I don't know"** when the documents don't contain the answer.
- 🔌 **Pluggable providers** — embeddings (`ollama` / `sentence-transformers`) and
  LLM (`ollama` / `openai`) are swappable via environment variables.
- 🗑️ **Manage documents** — list and delete indexed documents at any time.
- 🧪 **Tested** (pytest) and **containerized** (Docker Compose).
- 🛡️ Clean error handling, request IDs, health/readiness probes, CORS.

## Architecture

```
┌──────────────┐   HTTP    ┌────────────────────────┐
│  Streamlit   │ ────────► │       FastAPI API      │
│  chat UI     │ ◄──────── │                        │
└──────────────┘           │  ingest → chunk        │
                           │  embed  → FAISS search │
                           │  retrieve → LLM answer │
                           └───────────┬────────────┘
                                       │  HTTP
                                       ▼
                             ┌───────────────────┐
                             │   Ollama (local)  │
                             │  embeddings + LLM │
                             └───────────────────┘
```

**Flow:** upload → extract text → chunk → embed → store in FAISS. Ask → embed the
question → retrieve the top-k chunks → if relevant, send them to the LLM with a
strict "use only this context" prompt → return the answer plus its sources.

## Tech stack

| Layer      | Technology                                                        |
| ---------- | ----------------------------------------------------------------- |
| Backend    | Python 3.11, FastAPI, Uvicorn, Pydantic                           |
| Retrieval  | FAISS (cosine via normalized inner product), NumPy                |
| Embeddings | Ollama (`nomic-embed-text`) or `sentence-transformers` (optional) |
| LLM        | Ollama (`llama3.1`) or OpenAI (optional)                          |
| Documents  | pypdf (PDF), plain text, Markdown                                 |
| Frontend   | Streamlit                                                         |
| Tests      | pytest (runs offline with fakes)                                  |
| Deploy     | Docker + Docker Compose                                           |

## Getting started

### Prerequisites

- Python 3.11+
- [Ollama](https://ollama.com/) running locally, with the models pulled:
  ```bash
  ollama pull nomic-embed-text
  ollama pull llama3.1:8b
  ```
  (Any Ollama chat model works — set `OLLAMA_CHAT_MODEL` accordingly.)

### 1. Backend

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # macOS / Linux
pip install -r requirements.txt

uvicorn app.main:app --reload --port 8000
```

API: http://localhost:8000 — interactive docs at http://localhost:8000/docs.

Configuration is optional: copy `.env.example` to `.env` to change models,
chunk size, `TOP_K`, or switch providers. The defaults target local Ollama.

### 2. Frontend

```bash
cd frontend
pip install -r requirements.txt
streamlit run app.py
```

Open http://localhost:8501, upload a PDF, and start asking questions.

### Run with Docker

```bash
docker compose up --build
```

UI on http://localhost:8501, API on http://localhost:8000. Ollama is used from
the host automatically via `host.docker.internal`.

## API overview

| Method | Endpoint               | Purpose                                   |
| ------ | ---------------------- | ----------------------------------------- |
| POST   | `/documents/upload`    | Upload and index one or more documents    |
| GET    | `/documents`           | List indexed documents                    |
| DELETE | `/documents/{doc_id}`  | Delete a document and its chunks          |
| POST   | `/chat/ask`            | Ask a question; returns answer + sources  |
| GET    | `/health`              | Index stats (documents, chunks)           |
| GET    | `/ready`               | Whether the Ollama backend is reachable   |

Example:

```bash
curl -X POST http://localhost:8000/documents/upload -F "files=@mydoc.pdf"

curl -X POST http://localhost:8000/chat/ask \
  -H "Content-Type: application/json" \
  -d '{"question": "What is the refund policy?"}'
```

Errors use a consistent shape: `{"error": {"code": "...", "message": "..."}}`,
and every response carries an `X-Request-ID` header.

## Configuration

| Variable                | Default            | Description                                   |
| ----------------------- | ------------------ | --------------------------------------------- |
| `EMBEDDINGS_PROVIDER`   | `ollama`           | `ollama` or `sentence_transformers`           |
| `OLLAMA_EMBEDDING_MODEL`| `nomic-embed-text` | Embedding model name                          |
| `LLM_PROVIDER`          | `ollama`           | `ollama` or `openai`                          |
| `OLLAMA_CHAT_MODEL`     | `llama3.1:8b`      | Chat model name                               |
| `OPENAI_API_KEY`        | *(empty)*          | Required only when `LLM_PROVIDER=openai`      |
| `CHUNK_SIZE`            | `900`              | Characters per chunk                          |
| `CHUNK_OVERLAP`         | `150`              | Overlap between chunks                        |
| `TOP_K`                 | `4`                | Chunks retrieved per question                 |
| `SCORE_THRESHOLD`       | `0.25`             | Min similarity to treat context as relevant   |

## Running the tests

```bash
cd backend
pip install -r requirements-dev.txt
pytest
```

Tests use fake embedding/LLM providers, so they run **offline** — no Ollama or
network required.

## Notes & limitations

- Designed for personal / portfolio-scale document sets. The FAISS flat index is
  exact and simple; for very large corpora an approximate index (IVF/HNSW) would
  scale better.
- Switching embedding models changes vector dimensions — clear the index
  (`DELETE` documents or remove `backend/data/index`) before switching.
- Answer quality depends on the chosen LLM; `llama3.1:8b` gives a good local
  balance of speed and quality.
